> ✅ 지금 동작 · ⚠️ 동작하지만 문제 있음 · ❌ 미구현

## 먼저 결론

**문서 §37 "핵심 성공 경험"은 현재 빌드에서 일어날 수 없습니다.** 한 사용자가 쓴 SIGNAL을 다른 사용자가 읽으려면 저장소·계정·번역 API가 필요한데, 지금은 프론트엔드만 있습니다. 읽는 쪽 경험(번역 + 원문 보존)은 사전 작성된 SIGNAL 12개로 완전히 체험할 수 있지만, 쓰는 쪽과 읽는 쪽이 **연결되는** 순간은 없습니다.

백엔드 없이 고칠 수 있던 문제는 모두 해결했습니다(바이럴 루프 단절, SNS 미리보기, 재방문, 채널 대화 유지 포함). 남은 것은 백엔드가 필요한 P0와 V0.2 예정인 검색뿐입니다 — 맨 아래 [발견된 문제](#발견된-문제).

## S1. 핵심 성공 경험 — 서울 작성자 → 도쿄 독자 (§37)

**페르소나** P1 민지 + P2 켄타
**성공 기준** 민지가 한국어로 쓴 SIGNAL을 켄타가 일본어로 읽고, 일본어로 답하고, 민지가 그 답을 한국어로 읽는다.

| # | 누가 | 행동 | 경로 | 상태 |
|---|---|---|---|---|
| 1 | 민지 | 첫 접속, 한국어 자동 감지 | `/` | ✅ |
| 2 | 민지 | 종족 선택 후 진입 | `/` → `/ko` | ✅ |
| 3 | 민지 | 한국어로 SIGNAL 작성, 노드 `SEOUL` 선택 | `/ko/signal` | ✅ 이 브라우저에 저장, 페이지 이동 후에도 유지 (다른 사람에겐 안 보임) |
| 4 | 켄타 | 민지의 SIGNAL을 일본어로 읽음 | `/ja/signal` | ❌ 저장·전달·번역 백엔드 없음 |
| 5 | 켄타 | 일본어로 댓글(TRANSMISSION) | — | ❌ 댓글 기능 없음 |
| 6 | 민지 | 켄타의 댓글을 한국어로 읽음 | — | ❌ |
| 7 | 둘 | 서로 SIGNAL을 보냄 (WATCH) | — | ❌ |
| 8 | 둘 | PRIVATE CHANNEL에서 각자 언어로 대화 | `/[locale]/channel` | ❌ 채널은 스크립트 엔티티와만 연결됨 |

**지금 대신 체험 가능한 것**
켄타 입장의 4번은 사전 작성된 SIGNAL로 완전히 재현됩니다 — `@coldblooded96`(서울, 한국어 원문)을 일본어로 읽고 `原文の信号を見る`로 한국어 원문과 나란히 비교. 번역 레이어의 계약(원문 보존, 번역 표시, 대기 상태)은 [`resolveTranslation()`](../src/lib/i18n.ts)에 구현돼 있어서, 데이터 소스만 API로 바꾸면 UI는 그대로 씁니다.

**이 시나리오를 살리려면** 계정, SIGNAL 저장(Postgres), 온디맨드 번역 + 캐시(§8), 댓글. 문서 기준으로 전부 V0.1 범위입니다.

## S3. 공유 카드 유입 — 바이럴 루프 (§22, §26)

**페르소나** 서울의 친구 → P3 발레리아
**성공 기준** 발레리아가 친구의 결과를 보고 → 스페인어로 된 랜딩에 도착 → 직접 스캔 → 자기 결과를 공유.

| # | 누가 | 행동 | 상태 |
|---|---|---|---|
| 1 | 친구 | `/ko/scan` 5문항 완료, `REPTILIAN INDEX 70.7%` | ✅ |
| 2 | 친구 | `공유 링크 복사` → `https://reptilink.vercel.app/?index=70.7` | ✅ |
| 3 | 친구 | 인스타 스토리에 링크 게시 | ✅ 링크가 결과 카드로 펼쳐짐 — 70.7%, CLASS, ENTITY ID, 보낸 사람 언어의 문구 |
| 4 | 발레리아 | 링크 클릭, 스페인어 감지 | ✅ |
| 5 | 발레리아 | 친구의 70.7%를 봄 | ✅ `/?r=ko01230` → `/es/scan?r=ko01230`. 스페인어 라벨로 친구의 카드 전체, 언어 칸은 `한국어` |
| 6 | 발레리아 | 카드 아래 `INICIAR ESCANEO DE IDENTIDAD` | ✅ 바로 자기 스캔 시작, URL에서 `?r=` 제거 |
| 7 | 발레리아 | 결과 공유 → `/?r=es32103` | ✅ 스페인어 카드로 펼쳐지고, 받는 사람 쪽에서 루프가 다시 시작 |

**해결됨** 링크에 점수 대신 답변과 보낸 사람 언어를 담아서(`ko01230`), 받는 쪽이 카드 전체를 다시 계산합니다. 링크를 조작해서 나올 수 없는 점수를 만들 수도 없습니다.

미리보기 카드는 **보낸 사람의 언어**로 그립니다. 링크를 보는 사람은 대개 보낸 사람의 팔로워이기 때문입니다. 링크를 연 뒤의 페이지는 **받는 사람의 언어**로 나옵니다.

## S6. 렙틸리언과의 조우

**페르소나** P6 루카스
**성공 기준** 게이트에서 `REPTILIANO`를 고르고, 채널에서 그 존재와 포르투갈어로 대화하며 "나를 알아본다"고 느낀다.

| # | 행동 | 상태 |
|---|---|---|
| 1 | 게이트에서 `REPTILIANO` → 동공 확장, `ENTITY RECOGNISED` | ✅ |
| 2 | 내비 `CHANNEL` | ✅ |
| 3 | 엔티티가 먼저 말함, 원문 글리프 보존 | ✅ |
| 4 | "quem é você" / "você é real?" / "o que eu sou" | ✅ 각각 맞는 응답 |
| 5 | 엔티티가 루카스가 렙틸리언을 골랐다는 걸 앎 | ✅ 첫 마디가 *"Na entrada você disse o que é. Eu esperava que dissesse onde eu pudesse ouvir."* · `DECLARADO: REPTILIANO` |
| 6 | 대화 중 언어를 `KO`로 바꿈 | ✅ 대화 유지. 엔티티의 말은 한국어로 다시 그려지고, 루카스가 쓴 말은 포르투갈어 원문 그대로 `· PORTUGUÊS` 표시 |
| 7 | 다른 탭 갔다가 채널로 복귀 | ✅ 이 브라우저에 저장돼 그대로 이어짐. `채널 닫기`로 지울 수 있음 |

**해결됨** 게이트에서 한 약속("당신이 말하기를 기다렸다")을 채널이 받아서 이어갑니다. 네 가지 종족마다 첫 마디가 다르고, 게이트를 거치지 않은 방문자에게는 기본 첫 마디가 나갑니다.

엔티티의 원문 글리프는 읽는 언어와 상관없이 항상 같습니다. 원문은 하나고, 바뀌는 건 그 위의 번역뿐입니다.

## 발견된 문제

### P0 — 핵심 가치가 성립하지 않음

| 문제 | 영향 시나리오 | 필요한 것 |
|---|---|---|
| 사용자 간 SIGNAL 전달 불가 | S1 전체 | 계정, 저장소, 번역 API + 캐시, 댓글 (문서상 V0.1) |

### 해결됨

| # | 문제 | 어떻게 |
|---|---|---|
| 1 | 공유 링크 수신자가 결과를 못 봄 → 바이럴 루프 단절 | 링크에 답변+언어를 담고, Entry가 수신자 언어의 결과 페이지로 보냄 |
| 2 | 작성한 SIGNAL이 항상 서울/KST로 표시 | 언어별 기본 노드 + 직접 선택, 시간대는 사용자 실제 시계 |
| 3 | 종족 선택이 저장만 되고 쓰이지 않음 | 채널 엔티티의 첫 마디와 `DECLARED` 칸이 선언한 종족을 반영 |
| 4 | 작성한 SIGNAL이 페이지 이동 시 사라짐 | 이 브라우저에 저장, 본인 글은 삭제 가능. 손상된 저장 데이터는 무시 |

### P2 — 해결됨

| # | 문제 | 어떻게 |
|---|---|---|
| 5 | SNS 미리보기 이미지 없음 | 로케일별 기본 카드, 공유 스캔 카드(보낸 사람 언어), 아카이브 노드별 카드(제목·분류·요약). 한·일·태 글꼴은 카드에 쓰인 글자만 받아옴 |
| 6 | 재방문자도 매번 부팅 | 선언을 마친 재방문자는 `RECONNECTING` 후 바로 입장 |
| 7 | 채널 대화 소실 | 말한 문장이 아니라 *무엇을 말했는지*를 저장 — 언어를 바꾸면 엔티티의 말이 새 언어로 다시 그려짐 |
